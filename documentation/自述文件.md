## 实用方案

一个问题一页,标题就是用户会打出来的话。每一页都带着它那个场景的代码,以及这个构建真实跑出来
的输出,所以实用方案里没有任何一处是手写出来的:[`zh-CN/实用方案/`](zh-CN/实用方案/)。

| 文档 | 涵盖内容 |
|---|---|
| [给这个服务加日志](zh-CN/实用方案/给这个服务加日志.md) | 一个没有任何日志语句的结算,只包装一次:每次调用连同它的参数和结果都经由你自己的 logger 出现 |
| [帮我调试并修复这个缺陷](zh-CN/实用方案/帮我调试并修复这个缺陷.md) | 一张被拒付的卡让库存一直被占着——异常从不提的那个业务缺陷,在追踪里找到、修好并钉住 |
| [这个测试为什么失败了](zh-CN/实用方案/这个测试为什么失败了.md) | 拿着断言一个 span 一个 span 地读一个红了的结算测试:代码做的就是它说的,过时的是期望 |
| [修改复杂流程前先审查它](zh-CN/实用方案/修改复杂流程前先审查它.md) | 同一次运行在 `DETAIL` 和 `SUMMARY` 下的样子,带值的日志行与不带值的 `.nt` 并排 |
| [审查重构:行为变了吗](zh-CN/实用方案/审查重构行为变了吗.md) | 测试仍然是绿的,而审批差异点名了被删掉的那次调用,由你批准或否决 |
