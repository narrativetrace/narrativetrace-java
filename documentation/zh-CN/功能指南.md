# NarrativeTrace 功能指南

[English](../feature-guide.md) | [Español](../es/guia-de-funcionalidades.md) | **简体中文**

**范围:产品。** 本指南是 NarrativeTrace 功能面向所有平台(Java、TypeScript、Python、.NET)的规范目录。

本目录只有一个家,以免散成各平台的副本:在所有平台上都成立的决定只在这里记录一次;只属于某个平台具体实现的机制,则留在该平台自己的文档里。每一行已发布的功能都注明实现它的 Java 类(`module: main classes`),读者可以从表格行直达本仓库中的代码。表格行描述功能*是什么*;各平台在行为*如何*上的一致,归属于基于规范 JSON schema 的一致性测试夹具(conformance fixtures),而不是这里的文字。

本指南按你想完成的目标组织,而不是按模块。

**状态标签:**

- **开放** —— 已发布,Apache 2.0,位于 `narrativetrace-api`:注解、事件模型、
  输出格式规范与各 SPI。作为开放标准,任何实现都可以对齐它。
- **免费** —— 已发布,源码可得(BSL 1.1,四年后转为 Apache 2.0),可在本仓库中
  使用。可免费用于生产。
- **免费/闭源** —— 免费发布、专有,在本仓库之外构建。
- **Pro** —— 已在 NarrativeTrace Pro(商业层级)中发布。
- **开发中** —— 正在积极构建;设计已定。
- **已规划** —— 已有规格说明,尚未开始;可能变更。

本仓库中各模块属于哪个类别声明在 `licensing.properties` 中,并且构建会拒绝许可证
无法支撑的依赖关系图。

本指南对照 Java 代码的最近一次完整审计:**2026-08-18**。

## 捕获你代码的故事(核心追踪)

| 功能 | 状态 | Java 实现 | 说明 |
|---|---|---|---|
| 自动叙事捕获——方法、类、参数名称、返回值、耗时、错误;零日志语句 | 免费 | `proxy: NarrativeTraceProxy` · `agent: NarrativeClassFileTransformer` · `core: NarrativeContext, TraceEvent` | Tier 1:无需注解、无需配置。参数名称需要 `-parameters`(Gradle 插件会自动添加) |
| 增强注解——`@Narrated`、带 `{param}` 模板的 `@OnError`/`@OnErrors`、`@NarrativeSummary` | 免费 | `core: Narrated, OnError, NarrativeSummary, TemplateParser` | 未解析的占位符会在测试时报告(`TemplateWarningCollector`);叙述在每个被追踪的调用上渲染,包括叶子调用。[annotations-guide.md](注解指南.md) |
| 敏感数据脱敏——`@NotTraced`(所有输出,始终生效)+ 基于名称的脱敏规则 | 免费 | `core: NotTraced, RedactionPolicy` | 对字段名做不区分大小写的子串拒绝列表;内置默认项(password、token、ssn 等)+ 自定义集合。`Map` 的键经由同一受保护路径渲染(脱敏 + 界限),绝不使用原始 `toString()`。单值包装器(`Optional`、原始类型可选值、`Future`、`AtomicReference`)以及列表形态与键值对形态的容器(`AtomicReferenceArray`、单独出现的 `Map.Entry`)会被打开,其内容按同样的规则渲染,因此脱敏不会在深入一层容器后失效 |
| void 完成契约——void 方法不携带渲染值(`null`,绝不是字符串 "null") | 免费 | `proxy` + `agent` 捕获;所有渲染器/导出器均遵循 | Markdown/文本不渲染任何内容,JSON 省略 `returnValue`,图表渲染 ✓,SLF4J 记录“← completed”;渲染出的 `"null"` 始终表示真实的 null 返回值 |
| 输出注入加固——渲染值无法伪造日志行,也无法破坏 Markdown/图表语法 | 免费 | `core: MarkdownEscape, ControlEscape` · `diagrams: DiagramText` | 控制字符净化、HTML 转义、动态加宽代码围栏(code fence) |

| 双闸门级别架构——捕获级别与日志级别相互独立 | 免费 | `core: NarrativeTraceConfig` · `slf4j: Slf4jTraceEventListener` | ADR-008。[configuration-guide.md](配置指南.md) |
| 配置解析——系统属性 → `narrativetrace.properties`,重复配置立即失败 | 免费 | `core: ConfigResolver, DuplicateConfigurationException` | classpath 上出现两个配置文件是硬错误,而不是静默的优先级 |
| 并发捕获——fork-join(分叉汇合)与即发即弃(fire-and-forget)分组、跨线程嫁接、虚拟线程、等待时间与顺序化异步诊断 | 免费 | `core: ForkGroup, FireAndForgetGroup, ContextSnapshot` · `render: SequentialAsyncDetector` | 经 jcstress 验证;等待时间与顺序化异步分析在渲染时进行(Markdown 输出)。`captureTrace()` 以线程为作用域——请在记录线程上捕获,或通过 `ContextSnapshot.wrap()` 嫁接 |
| 追踪身份——traceId、人类可读的追踪名称、storyId/chapterId 派生 | 免费 | `core: TraceId, SpanContext` · `export: CanonicalEntryMapper` | 与规范 schema 对齐 |

## 阅读故事(输出)

| 功能 | 状态 | Java 实现 | 说明 |
|---|---|---|---|
| 缩进文本与 Markdown 渲染器(接入测试输出);散文渲染器(库 API) | 免费 | `core: IndentedTextRenderer, MarkdownRenderer, ProseRenderer` | 散文尚不是 `narrativetrace.format` 的选项——仅提供 API 与示例。Markdown 将父调用的返回值内联渲染在入口行(不再有收尾重复行) |
| 跟踪值引用——对重复捕获值做基于内容的去重,并使用可读标签(首次出现渲染 `‹Hotel›=完整值`,之后为 `‹Hotel›`) | 免费 | `core: ValueReferenceIndex`(经由 `MarkdownRenderer`) | 标签取自结构化值的身份字段(name/id/description/…),绝不取自被脱敏字段;字节相等性证明同一性——任何差异都会完整渲染;包含在其他捕获值内也计数并被替换 |
| 追踪内值增量——同一实体再次被捕获且已发生变化时,渲染为相对参照定义的差异(`‹Dinner›′{amount: 100.0→92.0, currency: "USD"→"EUR"}`) | 免费 | `core: ValueDelta`(经由 `ValueReferenceIndex`、`MarkdownRenderer`) | “同一实体”指结构化类型名相同且身份字段取值相等——正是为标签命名的那一套身份阶梯;渲染字节不同则表示它发生了变化。差异由两份结构化值计算得出,只列出发生变化的标量字段(字符串、整数、小数、布尔、时刻、空值),绝不从结构化值反向重建扁平渲染。凡是无法表达的情形——嵌套对象或列表发生变化、字段集合不同、值没有身份字段——都会完整渲染,与本特性存在之前完全一致,也不会在无人回指的定义上盖一个标签。若变化后的变体本身重复出现,则直接以差异形式定义(`‹Dinner·2›=‹Dinner›′{…}`),因此它仍能获得可复用的标签;被折叠的循环迭代也在 `×k more` 行上以其差异命名。小数以 `double` 传递:捕获为 `100.00` 的 `BigDecimal` 在差异中打印为 `100.0`,而参照行仍显示原始文本。与跨运行差异不同,基线就在同一份文档内,因此产物仍然自包含。仅用于呈现且仅限 Markdown |
| 循环折叠——在 Markdown 中压缩重复的同构兄弟子树 | 免费 | `core: LoopFold、StructuralTraceRenderer#subtreeKey`(经由 `MarkdownRenderer`) | 由连续 ≥2 个结构完全相同的顺序兄弟节点组成的最长序列,会完整渲染第一个迭代,然后用一行 `×k more: ‹Dinner›, ‹Taxi› — same flow (validate ✓ → record ✓) — 12ms total, 2–5ms each` 概括其余迭代。“同构”即无值的结构投影(复用第 8 项的判定器):签名、子节点形状与结果种类都相同——发生分叉调用、单个抛出异常或结果种类不一致的迭代会在折叠之外完整渲染(异常即信号);而所有迭代都以相同方式抛出异常时仍会折叠。每个被折叠的迭代以其首个可区分参数命名——若文档已定义该实体,则以 `‹ref›′{…}` 差异形式呈现,否则通过身份阶梯(`ValueReferenceIndex`,与后续 `‹ref›` 使用保持一致)命名;当没有身份字段可用时(纯标量:一个 SKU、一个 id、一笔金额),则用位置加上参数本身来命名,`#2 sku="TENT"`,超过 32 个字符即省略,这样被省略的迭代是可达的而不只是被计数;只有当差异比根参数更深时才仍然是光秃秃的 `#n`。`narrativetrace.unfolded=true` 会彻底关闭折叠,把每一次迭代都完整渲染。时长做聚合(合计 + 范围,绝不逐迭代列出);标签上限为 6、流程尾部上限为 8,超出以 `…` 表示。仅用于呈现且仅限 Markdown——JSON、`.nt`、图表与翻译视图均不受影响;并发(fork 组、fire-and-forget)绝不折叠 |
| 按测试生成的追踪文件——带 YAML frontmatter 的全细节 Markdown + 规范 JSON + 每个场景一张 Mermaid 图 | 免费 | `core: TraceTestSupport, TraceFileWriter, FrontmatterBuilder` | `build/narrativetrace/traces/<Class>/<test>.md` + `.json` + `diagrams/` |
| 对 AI 安全的结构化追踪文件——每个测试单独生成不含值的工件,外加实时结构化流 | 免费 | `core: StructuralTraceRenderer, StructuralProjection, TraceTestSupport` · `slf4j: StructuralSubscriber` | 每个场景生成 `structural/<类名>/<场景>.nt`——仅包含名称、调用层级与结果种类;确定性输出(行为相同则字节相同);格式规范:[structural-trace-format.md](../structural-trace-format.md)。`narrativetrace.structuralJson=true` 还会生成 `<test>.structural.json`——schema 1.2 条目,所有运行时值字段均已剔除(ADR-002 第 1 级;1.2 新增字段均为身份性质,会保留在投影中);挂在管道接缝上的 `StructuralSubscriber` 将同一投影实时输出为 `narrativetrace.ai.structural` logger 上的 JSON 行 |
| 规范 JSON 导出(章节树 schema) | 免费 | `core: JsonExporter, ChapterExporter, CanonicalEntry, CanonicalEntryMapper` | 按测试的 `.json` 已接入,并由一道针对真实写入器的一致性门校验其符合 `chapter-tree.schema.json`;`narrativetrace.canonicalJson=true` 还会为每个测试写出 `.canonical.json`(扁平的规范条目——移植版与一致性夹具使用的格式)。`nt.schemaVersion` 在条目与章节对象间全局统一——处处为 1.2,由 `CanonicalEntry.SCHEMA_VERSION` 盖章(= 1.1 + 捕获广度身份字段)。章节身份是即时生成的:`trace_id`、`nt.storyId` 与 `nt.chapterId` 始终写出——trace id 采纳、继承或生成(绝不是共享常量),story 由第一个根级调用推导,chapter 与其相等——且每棵树只解析一次,因此章节与其自身条目始终指向同一条 trace。章节导出器是库 API,尚无生产调用方 |
| 每个场景的时序图——Mermaid + PlantUML | 免费 | `diagrams: MermaidSequenceDiagramRenderer, PlantUmlSequenceDiagramRenderer` | Mermaid 按场景自动生成;PlantUML 通过 `narrativetrace.format=plantuml` 启用(替代 Markdown 追踪) |
| 带清晰度评分与失败叙事的控制台测试摘要 | 免费 | `core: ConsoleSummaryReporter` · `output: TraceTestSupport` | 失败时报告会定位变化:存在基线时打印相对上次绿色运行的结构增量(摘要 + 可读 diff),否则打印完整追踪;追踪文件路径以可点击的 `file://` 链接形式输出 |

## 让本指南保持诚实

本指南的存在,是为了不让任何功能在代码、计划与愿景文档之间被遗漏——也为了不让任何未发布的功能读起来像已发布。规则如下:

1. 每个用户可见的功能都在此出现,且恰好出现一次,并标注状态。
2. 功能只有在合并、测试并写好文档之后才能进入**免费**/**Pro**。“开发中”表示设计已定且工作已排期;“已规划”表示仅有规格说明。
3. 新增或提升功能状态的变更必须在同一个 commit 中更新本文件。
4. **以代码为准。** 每一行已发布的免费功能都注明实现它的 Java 类(`module: main classes`)。当指南与代码不一致时,代码是对的,指南就是 bug——修正表格行,并在文件头记录审计日期。
5. **只有一份目录,绝不按平台复制。** 本指南说明产品是什么;每个平台在各自仓库中记录自己的机制。各平台的已发布/待完成状态属于维护者的状态矩阵,一份私有工作记录——而不是本目录的副本。
