# NarrativeTrace Java 开发者体验

[English](../developer-experience.md) | [Español](../es/experiencia-de-desarrollo.md) | **简体中文**

从一个空项目到读到你的第一份叙事需要做些什么,以及这份体验的每一部分分别落
在哪里。本页描述的是目前已经发布的能力;计划中的改进记录在 `TODO.md` 中。

## 一行代码搭建

应用 Gradle 插件并写一个测试。插件会添加 NarrativeTrace 制品、配置 JUnit
Platform,并提供 Jupiter 测试引擎——这份文档化的最小配置无需任何额外依赖就
能让一个真实测试跑绿。每种构建风格对应的确切代码片段见安装指南。

## 逐测试叙事

`narrativetrace-junit5` 模块会在每个测试运行时为它写出一份叙事。产物落在构
建输出旁边,采用规范格式(`.nt` 叙事文本、结构化与规范 JSON、章节文档)——这
些格式与每个 NarrativeTrace 移植版所产出的完全一致,并由本仓库自带的 schema
校验。

## 无需项目即可试用

`./demo.sh` 会启动示例应用(电商及其它几个)并把真实场景叙述到控制台——这是
在你接线任何东西之前,最快看到输出长什么样的方式。

## 使用本地构建

评估尚未发布的改动,或针对本仓库构建一个集成,要用到 Gradle 的组合构建
(composite build)——并且需要**两种**引入角色同时具备:一个
`pluginManagement { includeBuild(...) }` 让插件能被解析,以及一个顶层的
`includeBuild(...)`,让插件添加的库坐标替换为指向你本地检出的版本。完整的
`settings.gradle.kts` 配方见插件文档。

## 开发期间的安全保障

脱敏是开发体验的一部分,而不是事后补丁:一个 `@NotTraced` 成员绝不会出现在
任何渲染输出里——不会通过包装器的 `toString()` 泄露,不会通过集合泄露,也不
会通过指名了它的路径的叙述模板泄露。如果某份叙事确实需要这个值,唯一刻意
的、可审查的做法是移除注解本身,而绝不是绕开它。
