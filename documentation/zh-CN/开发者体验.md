# NarrativeTrace Java 开发者体验

[English](../developer-experience.md) | [Español](../es/experiencia-de-desarrollo.md) | **简体中文**

从一个空项目到读到你的第一份叙事需要做些什么,以及这份体验的每一部分分别落
在哪里。本页描述的是目前已经发布的能力;计划中的改进记录在私有的待办清单中。

## 一行代码搭建

应用 Gradle 插件并写一个测试。插件会添加 NarrativeTrace 制品、配置 JUnit
Platform,并为默认的 JUnit 5 模式提供 Jupiter 测试引擎——这份文档化的最小配置无需任何额外依赖就
能让一个真实测试跑绿。每种构建风格对应的确切代码片段见安装指南。
要生成叙事,请在测试中注册 `NarrativeTraceExtension`,并执行被追踪的调用,
例如通过 `NarrativeTraceProxy.trace`。插件提供依赖和测试配置,但不会注册扩展。

对于已有的 JUnit 4 测试套件,保留该框架并设置
`narrativeTrace { testFramework.set("junit4") }`。将 public static 的
`@ClassRule NarrativeTraceClassRule` 与通过 `classRule.testRule()` 创建的
public `@Rule` 关联,然后通过逐测试规则的上下文追踪调用。
插件提供 JUnit 4 集成,但不会为测试添加这些规则。

## 逐测试叙事

注册扩展并启用输出(默认启用)后,`narrativetrace-junit5` 模块会为捕获到追踪的
测试写出叙事。产物落在构
建输出旁边,采用规范格式(`.nt` 叙事文本、结构化与规范 JSON、章节文档)——这
些格式与每个 NarrativeTrace 实现所产出的完全一致,并由本仓库自带的 schema
校验。

JUnit 4 的 `NarrativeTraceRule` 提供等效的逐测试上下文和输出。它读取测试 JVM
系统属性,而不是 `junit-platform.properties`。

## 命名反馈与智能体技能

在应用了 Gradle 插件的使用方项目中,`./gradlew clean clarityScan` 会对编译后的
生产类评分,无需运行测试。在配置的输出目录(默认为 `build/narrativetrace`)中
读取新生成的 `clarity-scan-report.md` 和 `clarity-scan-results.json`,即可查看
评分和逐元素说明。

若要分析实际执行的调用,已注册的 JUnit 扩展会分析非空的测试追踪,并在测试套件
完成时写出 `clarity-report.md` 和 `clarity-results.json`。在 JUnit 4 中,关联的
类规则在每个类完成后写出相同的报告,合并该测试 JVM 中已完成的类。独立的逐测试
规则不会生成汇总 Clarity 报告。Clarity 没有单独的
启用开关;`narrativetrace.output=false` 会同时禁用这些报告及其他追踪产物。

可选的 CI 强制检查使用 `./gradlew clean clarityCheck`。其默认输入是测试生成的
JSON。`minScore` 比较每个场景的 `overallScore`;问题数量限制单独检查。缺少
JSON 时任务会成功跳过,因此在依赖构建成功结果之前,请确认存在新生成的非空报告。
仅有静态扫描结果无法证明此质量门禁已通过。

[智能体技能](智能体技能.md)指南提供三个入口:

- `add-narrative-tracing` 安装追踪并生成第一份追踪。
- `narrativetrace-doctor` 诊断现有配置,不做修改。
- `add-narrativetrace-clarity` 生成并解释第一份命名报告,验证产物,
  并在用户提出要求时添加质量门禁。

评分与强制检查选项详见[清晰度指南](清晰度指南.md)。

## 无需项目即可试用

`./demo.sh` 会启动示例应用(电商及其它几个)并把真实场景叙述到控制台——这是
在你接线任何东西之前,最快看到输出长什么样的方式。

## 使用本地构建

评估尚未发布的改动,或针对本仓库构建一个集成,要用到 Gradle 的组合构建
(composite build)——并且需要**两种**引入角色同时具备:一个
`pluginManagement { includeBuild(...) }` 让插件能被解析,以及一个顶层的
`includeBuild(...)`,让插件添加的库坐标替换为指向你本地检出的版本。完整的
`settings.gradle.kts` 配方见插件文档。

## 开发期间的安全保障

脱敏是开发体验的一部分,而不是事后补丁:一个 `@NotTraced` 成员绝不会出现在
任何渲染输出里——不会通过包装器的 `toString()` 泄露,不会通过集合泄露,也不
会通过包含它的类自己手写的 `toString()` 泄露,还不会通过指名了它的路径的叙
述模板泄露。如果某份叙事确实需要这个值,唯一刻意
的、可审查的做法是移除注解本身,而绝不是绕开它。
