# 双路径事件管道

[English](../dual-path-pipeline.md) | [Español](../es/canalizacion-de-doble-ruta.md) | [Português](../pt-BR/pipeline-de-caminho-duplo.md) | **简体中文**

每个被追踪的调用只把事件发布一次,经由同一条管道。默认管道——每个发行版
中的 `DualPathPipeline`——会把每个事件投递两次,沿着两条保证刻意相反的
路径。本页是这两条路径的契约:各自承诺什么、各自付出什么代价,以及在高
负载下和进程崩溃之后会发生什么。

## 整体形状

```
 被追踪的方法(调用线程)
      │
      ▼
 捕获:值在此处渲染并【脱敏】,只做一次   ← 在任何其他环节看到它们之前
      │
      ▼
 发布(一个 TraceEvent)
      ├──────────────► 同步路径:SLF4J 叙事,内联执行,
      │                写入完成后方法才返回
      └──────────────► 缓冲路径:有界环形缓冲 → 事件存储、
                       追踪树、导出器、SPI 监听器
```

一个事件,两次投递。两条路径彼此隔离,也与你的应用隔离:任一消费者抛出
的异常都会被收容,绝不会变成应用程序的故障。

## 同步路径——在崩溃中幸存的叙事

SLF4J 监听器在调用线程上内联执行。日志写入在被追踪的方法返回之前完成,
因此这段叙事的持久性——以及成本——与你手写的一条日志调用完全相同。即使
进程在下一条指令处死亡,此前叙述的一切都已经在你的日志流里。

按事件类型的日志级别可以配置;默认值为 `ENTRY`/`RETURN` 用 TRACE、
`EXCEPTION` 用 WARN,记录在 `narrativetrace` 这个 logger 上。格式化、
appender 以及任何加锁都属于你的日志后端——监听器本身除线程内上下文外
不持有任何共享可变状态。

## 缓冲路径——永不阻塞的捕获

缓冲路径支撑着 `captureTrace()` 以及构建在其上的一切:追踪树、导出器、
通过 SPI 挂接的监听器。它的载体是一个有界环形缓冲——默认 65,536 个槽位
(`narrativetrace.buffer.capacity`),约 1.75 MB,按饱和时每事件约
300 字节做预算——由单一消费者线程排空。它永不增长,也永不阻塞调用线程。

在压力之下它选择卸载负载,而不是施加背压:

| 占用率 | 行为 |
|---|---|
| 70% 以内 | 完整处理——存储、建树、通知订阅者 |
| 70–90% | 卸载:事件被成批排出并丢弃 |
| 90% 以上 | 紧急:丢弃一切,直到压力解除 |

环形缓冲本身在写满时覆盖最旧的槽位而不是扩容,因此生产者总能写入。饱
和时丢失事件是这条路径有意为之的行为——另一种选择是让你的请求线程为可
观测性排队等待。

## 丢失被计数,绝不无声

每一个被丢弃的事件都会被计数——环形覆盖、成批卸载、订阅者背压丢弃,一
视同仁——并汇总在 `BufferedEventConsumer.droppedCount()` 中。追踪自身
的页脚会报告丢失,只有在毫无丢失时才省略:一条短的追踪绝不会与一条安
静的追踪悄无声息地混淆。

## 崩溃的代价

两条路径对崩溃问题的回答刻意不同:

- **同步路径:** 已经叙述的内容一样也不丢。写入发生在方法继续执行之前。
- **缓冲路径:** 进行中的追踪树是尽力而为的。崩溃瞬间仍在环形缓冲里的
  事件会丢失——这是为了永不阻塞调用者而写明的交换条件。

## 脱敏发生在分叉之前

参数值在捕获时渲染——并脱敏——只做一次,先于事件发布。被名称、注解或值
本身形状拒绝的值根本不会进入事件,因此任何一条路径、任何导出器、任何
SPI 监听器都永远看不到它。逐个表面列出的完整契约见
[隐私与脱敏](隐私与脱敏.md)。

## 消费者的挂接点

两个接缝,都是公开 API:

- **`TraceEventListener`**——逐事件,经由 `ServiceLoader` 发现,在缓冲
  路径的消费者线程上投递。抛出异常的监听器会被报告一次,并在 JVM 的余
  下生命周期中被禁用;一个行为不端的消费者绝不会把管道一起拖垮。
- **`TraceExporter`**——按完成的追踪,在请求边界处调用(servlet 过滤器
  以完整的追踪树调用它)。

## 配置

| 键 | 作用 |
|---|---|
| `narrativetrace.pipeline` | 按名称选择一个已注册的管道拓扑;不设置则构建本页描述的默认双路径拓扑 |
| `narrativetrace.buffer.capacity` | 缓冲路径的环形缓冲大小 |
| `narrativetrace.narration` | `off` 关闭 SLF4J 叙事监听器 |

管道是同一接口背后的一个组件:本页记述的是默认拓扑,而上文的一切——捕
获时脱敏、被计数的丢失、消费者隔离——无论部署选择哪种拓扑都同样成立。
所有键只在启动时读取一次;每个配置表面详见[配置指南](配置指南.md)。
