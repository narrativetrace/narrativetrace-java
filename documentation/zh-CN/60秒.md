# 60 秒看一条追踪

[English](../sixty-seconds.md) | [Español](../es/sesenta-segundos.md) | [Português](../pt-BR/sessenta-segundos.md) | **简体中文**

没有日志语句,没有测试框架,之后也不用打开任何文件:一个普通的 Java
`main`,一次调用,追踪就出现在你的终端里。下面的一切都针对 Maven Central
上已发布的制品真实运行过——输出是粘贴上去的,不是想象出来的。

## 1. 新建项目,添加依赖

Java 17+。两个制品——运行时核心,以及包装普通接口的 JDK 代理:

```kotlin
// build.gradle.kts
plugins {
    java
    application
}

repositories {
    mavenCentral()
}

dependencies {
    implementation("ai.narrativetrace:narrativetrace-core:0.2.1")
    implementation("ai.narrativetrace:narrativetrace-proxy:0.2.1")
}

tasks.withType<JavaCompile> {
    options.compilerArgs.add("-parameters")   // 没有它,追踪会显示 arg0、arg1
}

application {
    mainClass.set("com.example.orders.Main")
}
```

## 2. 程序本身

一个接口和一个实现——代理会包装这个接口,所以 `OrderService` 需要一个接口:

```java
// src/main/java/com/example/orders/OrderService.java
package com.example.orders;

public interface OrderService {
  String placeOrder(String customerId, String productId, int quantity);
}
```

```java
// src/main/java/com/example/orders/DefaultOrderService.java
package com.example.orders;

public class DefaultOrderService implements OrderService {
  @Override
  public String placeOrder(String customerId, String productId, int quantity) {
    return "ORD-" + customerId + "-" + productId + "-" + quantity;
  }
}
```

```java
// src/main/java/com/example/orders/Main.java
package com.example.orders;

import ai.narrativetrace.core.context.ThreadLocalNarrativeContext;
import ai.narrativetrace.core.render.IndentedTextRenderer;
import ai.narrativetrace.proxy.NarrativeTraceProxy;

public class Main {
  public static void main(String[] args) {
    var context = new ThreadLocalNarrativeContext();
    OrderService service =
        NarrativeTraceProxy.trace(new DefaultOrderService(), OrderService.class, context);

    service.placeOrder("C-1234", "SKU-KB", 2);

    System.out.println(new IndentedTextRenderer().render(context.captureTrace()));
    context.reset();
  }
}
```

`ThreadLocalNarrativeContext` 是追踪累积的地方。`NarrativeTraceProxy.trace(...)`
把真正的实现包装在接口背后,于是每一次经过 `service` 的调用都会被捕获。
`captureTrace()` 返回捕获完成的树;`IndentedTextRenderer` 把它渲染成文本。

## 3. 运行它

这个目录里还没有 `./gradlew`——先生成一次 wrapper(需要本机已安装
Gradle;见 [gradle.org/install](https://gradle.org/install/)):

```bash
gradle wrapper
```

```bash
./gradlew run
```

```text
OrderService.placeOrder(customerId: "C-1234", productId: "SKU-KB", quantity: 2) → "ORD-C-1234-SKU-KB-2" — 23ms
```

这就是上面那次运行真实、未经编辑的输出。耗时(`23ms`)是唯一会在你的机器上、
在每次运行之间发生变化的部分。

你没有写过一行日志语句。这份叙事来自方法名(`placeOrder`)、参数名
(`customerId`、`productId`、`quantity`)以及方法返回的值——仅此而已。

## 刚才发生了什么

- **`ThreadLocalNarrativeContext`** 是记录用的上下文——每个线程一个,保存
  在它上面运行过的一切,直到你把结果读出来。
- **`NarrativeTraceProxy.trace(...)`** 把 `OrderService` 包装进一个 JDK
  动态代理:每一次经由被包装引用发起的调用,都会在到达真正实现之前被捕获。
- **`context.captureTrace()` 加一个渲染器** 把捕获到的调用变成输出。
  `IndentedTextRenderer` 就是上面用到的纯文本渲染器;同一棵树也可以渲染成
  Markdown、JSON 或 Mermaid 时序图——参见[结构化追踪格式](../structural-trace-format.md)
  (英文)以及 [Gradle 插件指南](../zh-CN/Gradle插件指南.md),了解其余格式
  以及插件如何按每个测试把它们写到磁盘上。

## 发送到你的日志库

还是同一个项目,一个依赖加一个配置文件——上面的 `Main.java` 不用改。
`narrativetrace-slf4j` 一旦出现在 classpath 上,就会自己接到管道上,所以
改动就这么多:

```diff
 dependencies {
     implementation("ai.narrativetrace:narrativetrace-core:0.2.1")
     implementation("ai.narrativetrace:narrativetrace-proxy:0.2.1")
+    runtimeOnly("ai.narrativetrace:narrativetrace-slf4j:0.2.1")
+    runtimeOnly("ch.qos.logback:logback-classic:1.5.38")
 }
```

```xml
<!-- src/main/resources/logback.xml -->
<configuration>
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{HH:mm:ss.SSS} %-5level [%logger] - %msg%n</pattern>
        </encoder>
    </appender>

    <logger name="narrativetrace" level="TRACE" />

    <root level="INFO">
        <appender-ref ref="CONSOLE" />
    </root>
</configuration>
```

```bash
./gradlew run
```

```text
22:24:53.632 TRACE [narrativetrace] - → OrderService.placeOrder(customerId: "C-1234", productId: "SKU-KB", quantity: 2)
22:24:53.637 TRACE [narrativetrace] - ← returned: "ORD-C-1234-SKU-KB-2"
OrderService.placeOrder(customerId: "C-1234", productId: "SKU-KB", quantity: 2) → "ORD-C-1234-SKU-KB-2" — 8ms
```

耗时和之前一样会变化。同一条追踪现在也进入了你已经在用的日志库——这里选
Logback,因为它是最常见的 SLF4J 后端——同时控制台那一行照常打印,分毫
未变。完整配置(日志级别、logger 名称、MDC 字段)见
[配置指南 §7](配置指南.md#7-slf4j-配置)。
