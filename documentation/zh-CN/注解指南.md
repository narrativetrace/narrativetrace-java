# NarrativeTrace Java 注解指南

[English](../annotations-guide.md) | [Español](../es/guia-de-anotaciones.md) | **简体中文**

本指南列出 NarrativeTrace Java 项目中可用的全部注解,并说明每个注解的使用时机与使用方式。

NarrativeTrace 遵循**代码即日志**的理念:方法名、参数名和返回值本身就应当讲清运行时的故事。请首先保持业务逻辑干净、富有表达力,注解只在例外情况下使用,而不是默认使用。只有当注解能带来具体的额外价值时才添加,例如有针对性的叙述文本、面向特定错误的上下文,或敏感数据脱敏。

## 注解一览

| 注解 | 模块 | 作用目标 | 用途 |
|---|---|---|---|
| `@Narrated` | `narrativetrace-core` | 方法 | 为被追踪的方法添加人类可读的叙述文本。 |
| `@OnError` | `narrativetrace-core` | 方法 | 在方法抛出异常时添加上下文相关的错误文本。 |
| `@NotTraced` | `narrativetrace-core` | 参数、字段、record 组件 | 将某个值标记为在追踪输出中脱敏;在反射式内省期间,字段和 record 组件上的该注解同样生效。 |
| `@NarrativeSummary` | `narrativetrace-core` | 方法 | 为追踪中的对象提供自定义的值渲染。 |
| `@EnableNarrativeTrace` | `narrativetrace-spring` | 类型(`@Configuration`) | 为选定的包启用 Spring 自动代理追踪。 |

## 核心注解

### `@Narrated`

当你希望追踪中出现一句明确的叙述,而不是只依赖方法名 + 参数时,在方法上使用 `@Narrated`。

```java
public interface OrderService {
    @Narrated("Placing order of {quantity} units for customer {customerId}")
    OrderResult placeOrder(String customerId, int quantity);
}
```

工作原理:

- 模板占位符使用参数名(例如 `{customerId}`)。
- 同时适用于代理追踪和基于 Agent 的追踪。
- 在所有级别上以人类可读的叙述文本丰富追踪输出。

### `@OnError`

使用 `@OnError` 为异常附加特定于上下文的消息。

```java
public interface PaymentService {
    @OnError(value = "Payment declined for {customerId}, amount was {amount}",
             exception = PaymentDeclinedException.class)
    @OnError(value = "Temporary payment failure for {customerId}",
             exception = ExternalServiceException.class)
    PaymentConfirmation charge(String customerId, double amount, @NotTraced String token);
}
```

工作原理:

- 你可以在同一个方法上声明多个 `@OnError` 注解(它是可重复注解)。
- 若有多个匹配,则选择最具体的异常类型。
- 只写 `@OnError("...")` 等价于 `exception = Throwable.class`。

容器注解 `@OnErrors` 隐藏在可重复的 `@OnError` 背后。在普通代码中你永远不会直接写它——直接叠加多个 `@OnError` 注解即可。

### `@NotTraced`

在敏感的**参数、字段或 record 组件**上使用 `@NotTraced`,使它们的值在所有地方都被脱敏。

```java
public interface AuthService {
    Session login(String username, @NotTraced String password);
}

// 也可用于嵌套在被追踪对象内部的字段或 record 组件:
record Card(String last4, @NotTraced String pan) {}
```

工作原理:

- 名称仍然可见;在每个渲染器和导出器中,值都会被替换为 `[REDACTED]`。
- 在字段或 record 组件上,脱敏发生在反射式内省期间,因此嵌套在被追踪 DTO 内部的机密会被隐藏,而不必抹去整个对象。
- 典型用例:密码、token、机密、卡片数据。

**反射式内省默认脱敏,而不是默认泄露。** 当被追踪的对象没有精心编写的 `toString()` 时,NarrativeTrace 会对其字段做反射——但内置的基于名称的拒绝列表(`RedactionPolicy`)会在渲染任何值之前,自动对常见的敏感名称(`password`、`cvv`、`ssn`、`token`、`secret`、`authorization`、`cardNumber`、`accountNumber`、`routingNumber`、`sessionId`、`jwt`、`cookie`、`pan`、`iban` 等)以及键名匹配的 `Map` 值进行脱敏。`Map` 的键与其他值一样经由同一受保护的渲染路径:作为键的对象在其自身字段上遵循 `@NotTraced` 与拒绝列表(绝不使用其原始 `toString()`),字符串键会被净化并限制长度。`@NotTraced` 用于覆盖拒绝列表无法凭名称识别的敏感字段。精心编写的 `toString()` 优先于内省——但有一个例外凌驾其上:只要类中声明了 `@NotTraced` 字段,仍然走内省路径,于是被遵循的是该注解,而不是那个 `toString()` 本来会打印的内容。基于名称的拒绝列表不会覆盖 `toString()`;只有这条注解会。可用 `new ValueRenderer(…, RedactionPolicy.ofPatterns(...))` 覆盖匹配模式,或用 `RedactionPolicy.DISABLED` 完全停用。

**有两类秘密是按其本身的样子被隐藏的,而不只是按名称。** 基于名称的拒绝列表看不见以 `value` 传入、以裸 `String` 返回、或无名地待在列表里的持有者令牌,因此还有第二条独立规则去看字节本身。它只识别三种形态:JWT(三段 base64url,且第一段以 `eyJ` 开头)、卡号(13–19 位数字,允许分隔符,且通过 Luhn 校验),以及 `Set-Cookie` 字符串(`名称=值` 后面跟着 `Path`、`Max-Age` 或 `HttpOnly` 之类的 cookie 属性)。其余一切照常渲染——这是一份很短的结构特征清单,而不是熵启发式,因为凭猜测抹掉的值会在你的叙事里留下一个你看不见的窟窿。有一个误判是刻意接受的:长度与卡号相同、又恰好通过 Luhn 校验的标识符。未通过 Luhn 校验的订单号仍然可见。`RedactionPolicy.DISABLED` 会连同基于名称的拒绝列表一起停用这条规则;`RedactionPolicy.ofPatterns(...)` 只替换名称,并保留这条规则。

**脱敏可以穿透一层容器。** `Optional`、`OptionalInt`/`OptionalLong`/`OptionalDouble`、`Future`、`AtomicReference`、`AtomicReferenceArray` 或单独出现的 `Map.Entry` 这类容器若被当作值对待,就会打印其内容的原始 `toString()`,因此 NarrativeTrace 会将其打开,并严格按照上述规则渲染其所包含的值。`AtomicReferenceArray` 的渲染结果与持有同样元素的 `Object[]` 完全一致;单独出现的 `Map.Entry` 渲染为 `键=值`,与它出现在 `Map` 内部时完全一致。`Optional<Card>` 渲染为 `Card(number: "4111", cvv: [REDACTED])`,绝不会是 `Optional[Card[number=4111, cvv=123]]`;空的包装器渲染为 `<empty>`。这一点很重要,因为 `Optional<T>` 正是查询方法惯用的返回类型,而被脱敏的数据恰恰从那里经过。

**脱敏优先于点名它的模板。** `@Narrated` 与 `@OnError` 会在原始参数上解析 `{param.property}` 路径,而一条抵达被脱敏成员的路径解析结果为 `[REDACTED]`——在任意深度都是如此,因此路径中途的某个被脱敏成员也会连带隐藏它下面所点名的一切。当占位符点名的是整个对象而不是对象内部的一条路径时,规则同样成立:`{card}` 渲染为 `Card(number: "4111", cvv: [REDACTED])`,绝不会使用对象自身那个对 `@NotTraced` 一无所知的 `toString()`。点名对象的占位符始终交由捕获该值时所用的同一个渲染器来渲染,因此模板与被捕获的参数对该值的呈现是一致的:`record` 在两者中都按结构叙述,形如 `Money(currency: "EUR", amount: 10)`。定义了自己的 `toString()` 且未隐藏任何内容的类,仍然沿用它自己的 `toString()` 来叙述。若想自行决定叙述内容——无论是 `record` 还是其他类型——请为该类型添加一个 `@NarrativeSummary` 方法,它在这里与在别处一样受到尊重。点名一条路径或一个对象,绝不会削弱直接作用于该值的规则。第三种占位符形式同样遵循这两条规则:直接点名某个值的裸 `{name}`,既由拒绝列表按读取字段名的方式读取该键来回答,也由该值自身的形态来回答,因此 `@Narrated("login {password}")` 与以 `{value}` 传入的 JWT 都会渲染为 `[REDACTED]`。如果你确实需要在叙述中呈现这个值,请从该组件上移除 `@NotTraced`;这一移除动作才是刻意做出、可供评审的决定,并且会清楚地出现在 diff 中。

### `@NarrativeSummary`

在一个返回简短摘要字符串的零参数方法上使用 `@NarrativeSummary`,用于值渲染。

```java
public record Customer(String id, String name, CustomerTier tier) {
    @NarrativeSummary
    public String toNarrativeSummary() {
        return "Customer[id=%s, tier=%s]".formatted(id, tier);
    }
}
```

工作原理:

- `ValueRenderer` 会查找带有 `@NarrativeSummary` 注解且没有参数的公共方法。
- 若找到,该方法的输出就会用于追踪。
- 若未找到,渲染会回退到 record/toString 行为。

## 纯净性契约——追踪期间的副作用

NarrativeTrace 在渲染追踪时,可能会调用你的对象上一小组固定的代码路径。请保持这些成员**纯净**——不含懒加载、访问计数器、缓存填充或 I/O 等副作用——就像面对调试器或序列化器时那样。

哪些会被调用,哪些不会:

- **字段内省从不调用你的代码。** 当被追踪的对象没有精心编写的 `toString()` 时,`ValueRenderer` 通过反射读取它的*字段*——这是一次纯粹的内存读取。会递增计数器或懒加载数据的 getter 不会被内省触碰。
- **NarrativeTrace 会调用的是:** 自定义的 `toString()`、`@NarrativeSummary` 方法、record 组件访问器,以及你在 `@Narrated`/`@OnError` 模板中写出的任何属性路径(`{order.total}` 的解析会先调用直接访问器方法 `total()`,再调用 JavaBean getter `getTotal()`)。这些是渲染期间唯一会运行用户代码的地方。
- **调用是有界且隔离的。** 输出有上限(字符串长度、集合元素数量、内省深度),抛出异常的 getter 或 `toString()` 永远不会导致被追踪的业务调用失败(模板会回退为字面量 `{placeholder}`;渲染会回退为类型名标记),并且值在调用点被立即(eager)渲染——任何副作用只发生一次,发生在确定的时间点,并且在调用线程上。
- **渲染从不强制执行延迟计算。** `Future` 只有在 `isDone()` 时才会被解包;不会阻塞等待任何东西,也不会触发任何计算。

如果某个成员无法保持纯净,就为它加上 `@NotTraced` 注解——被脱敏成员的值根本不会被读取——或者为该类型提供精心编写的 `toString()`/`@NarrativeSummary`,由你精确控制会访问到什么。在 `TracingLevel.OFF` 下(以及 `SUMMARY` 级别下的参数值),完全不进行参数渲染,因此热路径上不会触碰任何用户代码。

## Spring 注解

### `@EnableNarrativeTrace`

在 Spring 配置类上使用 `@EnableNarrativeTrace`,以便自动用 NarrativeTrace 代理包装 Bean。

```java
@Configuration
@EnableNarrativeTrace(basePackages = {"com.example.orders", "com.example.payments"})
public class AppConfig {
}
```

属性:

- `basePackages`——限定哪些 Bean 会被包装的包前缀。默认为被注解类所在的包。
- `loggerName`——追踪事件使用的 SLF4J logger 名称(默认为 `"narrativetrace"`)。当 `narrativetrace-slf4j` 位于 classpath 上时,自动创建的上下文会以该名称经由 SLF4J 叙述(`Slf4jTraceEventListener` 位于管道的同步路径上)。设为 `""` 可禁用叙述。

工作原理:

- 注册 NarrativeTrace 的 Spring 配置和 Bean 后置处理器。
- 只考虑 `basePackages` 内的 Bean。
- Bean 必须实现接口才能被代理(JDK 动态代理)。
- 当 `narrativetrace-slf4j` 位于 classpath 上时,自动创建的上下文会自动经由 SLF4J 叙述。定义你自己的 `narrativeContext` Bean 即可覆盖它。

## 完整示例

```java
public interface TransferService {
    @Narrated("Transferring {amount} from {fromAccountId} to {toAccountId}")
    @OnError(value = "Transfer rejected for source account {fromAccountId}",
             exception = IllegalStateException.class)
    TransferResult transfer(
            String fromAccountId,
            String toAccountId,
            double amount,
            @NotTraced String authToken
    );
}
```

这一个方法就组合了叙述、有针对性的错误上下文和参数脱敏。

## 模板校验

`@Narrated` 和 `@OnError` 的模板使用 `{paramName}` 和 `{param.property}` 占位符。如果某个占位符不匹配任何参数——例如把 `{customerId}` 写成了 `{custmerId}`——字面量 `{custmerId}` 会原样留在解析后的追踪输出中。

NarrativeTrace 会在测试期间自动检测这种情况。每个测试结束后,JUnit 5 扩展和 JUnit 4 规则会扫描每个追踪节点,查找未解析的 `{...}` 模式并打印警告:

```
WARNING: Unresolved template placeholder(s) detected:
  - OrderService.placeOrder: {custmerId} in narration
  - ExpenseService.pay: {expense.payer.name} in narration
      ↳ nested path not supported — only one property level resolves (e.g. {object.property})
```

只会解析单个属性层级:`{expense.payer}` 会对 `expense` 参数调用 `payer()`(或 `getPayer()`)。像 `{expense.payer.name}` 这样更深的路径永远无法解析——解析器会把 `payer.name` 当作一个不存在的访问器——因此占位符会在运行时原样保留(优雅降级,绝不抛异常)。由于这是一种结构性的书写错误,而不是某个值恰好为 `null`,测试期校验会为多层级路径额外标注 `nested path not supported` 提示。

**被脱敏的路径解析为 `[REDACTED]`**——既不是原值,也不是原样保留的占位符。点名对象本身的占位符(`{card}`)会被同样拒绝:NarrativeTrace 会在不包含被脱敏成员的情况下渲染该对象,而不是调用它的 `toString()`。脱敏规则的两半都会沿路径生效:字段或记录组件上的 `@NotTraced`,以及作用于任何注解都未覆盖的属性的基于名称的拒绝列表(`password`、`cvv`、`token` 等)。由于被拒绝的是整条路径,这一点对本来就永远无法解析的多层级路径同样成立:`{order.card.cvv}` 渲染为 `[REDACTED]`,而不是原样保留。至于没有点名任何参数的占位符,或其所有者并未声明的属性,仍会原样保留——那属于书写错误,背后并不存在任何值,上面那条警告也必须照常触发。

无需任何配置——只要扩展或规则处于激活状态,警告就会出现在控制台输出中。只要有测试执行到带注解的方法,就能立即发现占位符名称中的拼写错误(例如 `{order.stauts}`)以及无法解析的多层级路径。
