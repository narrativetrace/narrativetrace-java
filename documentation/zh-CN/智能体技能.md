# 智能体技能

*(since 0.2.2, unreleased)*

NarrativeTrace 提供**技能**(skills):可供智能体加载的流程,它们运行经过测试的命令,并把
完成的条件设在一个 `verify` 步骤上,而不是一份智能体可能读也可能不读的文档。技能被刻意设计得
很薄——检查、诊断或生成的逻辑都放在经过测试的库代码里;技能本身的工作只是知道何时该出手、调用
那些经过测试的代码、并在上下文中解读结果。

## 两个技能:配置与诊断

- **`add-narrative-tracing`** ——把 NarrativeTrace 安装进一个项目,并让它产出第一条追踪:用真实
  的工具链安装、用 `NarrativeTraceProxy.trace` 包装一个类、渲染并运行第一条追踪,然后接入一个真
  实的日志记录器(`narrativetrace-slf4j` 加 Logback)。最后运行 `narrativetrace-doctor` 并把接力
  棒交给它——这是两个技能之间的接缝。
- **`narrativetrace-doctor`** ——只做诊断,而且是**只读**的:它绝不编辑、生成或删除任何文件。运
  行经过测试的 CLI、读取它的报告,并走完普通 CLI 输出本身覆盖不到的部分:在测试里证明脱敏确实生
  效、在对渲染出的追踪做断言之前先读一遍它,以及审批追踪流程(标记为尚未研究——它自己的评测单元
  仍待完成)。

两者相辅相成:一个全新的项目从 `add-narrative-tracing` 开始;一个已经装好 NarrativeTrace、但哪里
不对劲的项目从 `narrativetrace-doctor` 开始。两条路径最终都会走到 doctor——从那时起,诊断就归它
管了。未来会有一个技能负责生成(编写那个证明脱敏生效的测试,而今天 doctor 只能提醒你去添加它)。

## 安装它们

- **Claude Code**:渲染出的 `SKILL.md` 文件就放在本仓库的
  [`.claude/skills/doctor/`](../../.claude/skills/doctor/SKILL.md) 和
  [`.claude/skills/add-narrative-tracing/`](../../.claude/skills/add-narrative-tracing/SKILL.md)
  里。把这两个目录中的任意一个复制到你自己项目的 `.claude/skills/<名称>/` 下,Claude 就会自动识
  别它,也可以直接用名字(`narrativetrace-doctor` / `add-narrative-tracing`)调用。
- **任意智能体、任意平台**:任何会读取 `AGENTS.md` 的智能体都会看到本仓库自己的 `AGENTS.md` 在
  `<!-- narrativetrace:skills:start -->` 标记之间携带的这条常驻提示——两个技能各自的名称和描
  述——这样即使某个智能体从未想过要去找,它也知道这两个技能是存在的。
- **Codex 和 Gemini** 会按一种偶发的、受配额限制的节奏针对同一份目录运行(见
  [Tier B——LLM 试验](../../narrativetrace-skills/evals/README.md)),而不是每次提交都跑;面向这
  两个平台的打包安装器还在路线图上,尚未构建——今天,复制渲染出的文件就是可行的路径。

## 它们是如何构建的

这两个技能都绝不手工编辑。
`narrativetrace-skills/src/main/java/ai/narrativetrace/skills/catalogue/AddNarrativeTracingSkill.java`
和 `.../NarrativeTraceDoctorSkill.java` 是两份唯一的真相来源;它们的类型化步骤渲染出
`.claude/skills/add-narrative-tracing/SKILL.md`、`.claude/skills/doctor/SKILL.md`,以及本仓库自
己 `AGENTS.md` 里的那个小节——一个漂移测试(`RenderDriftTest`,已接入 `./gradlew check`)会在这三
者中任何一个偏离类型化源头的那一刻让构建失败。另一个测试套件(`SkillReplayer`,Tier A2)会针对
`sixty-seconds` 这个 fixture,机械地重放某个步骤所命名的每一条命令、以及每一个机器可检查的
`verify`——就在今天,确定性地、不借助任何 LLM——它保持绿色,意味着这些说明此刻确实可以照着执行,
而不只是听起来说得通的文字。一条 A 级 lint 会把对私有规划笔记的引用、对本仓库 Pro 版兄弟项目的引
用、CI 配置文件名、以及 git 哈希都挡在这两个页面之外:说明理由的句子可以出现,但点出出处的引用不
行。
